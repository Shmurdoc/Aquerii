## Executive Summary

Aquerii is not a project management tool. It is not a CRM add-on. It is not an HR system bolted onto an invoicing module. Aquerii is the operating system for modern companies — a single, unified platform where every department works, every deal closes, every employee is managed, and every decision is informed by real-time data.

The opportunity is enormous. The average SMB and mid-market company uses 8–12 SaaS tools to run itself. They pay for all of them separately. They move data between them manually. They train employees on each one. They lose context every time they switch tabs. They pay integration fees on top of subscription fees. And after all of that, they still don't have a single source of truth.

Aquerii eliminates all of that. One platform. One login. One data model. Every module shares the same underlying data, so a deal in CRM can generate an invoice in ERP, trigger an onboarding workflow in HR, and create a project in the workspace — without a single copy-paste or API call.

This document defines what Aquerii must become, why it wins, and exactly how we get there.

## 1. Product Vision & Mission

### Vision

**A world where running a company is as intuitive as using your phone.**

Every business — from a 5-person agency to a 5,000-person enterprise — deserves software that works the way people work: fluidly, without friction, without silos, without a consultant to set it up.

### Mission

**Aquerii gives every team the tools to work, sell, hire, and grow — in one place, with zero overhead.**

### The Problem We're Solving

The SaaS landscape in 2026 is fractured. Companies are drowning in tools:

- **Project work** lives in Asana, Monday, ClickUp, or Jira
- **Sales pipelines** live in Salesforce, HubSpot, or Pipedrive
- **Finances** live in QuickBooks, Xero, or NetSuite
- **HR** lives in BambooHR, Gusto, or Workday
- **Documents** live in Notion, Confluence, or Google Docs
- **Meetings** get scheduled in Calendly, tracked in Zoom, and documented nowhere

Every one of these tools has its own login, its own data model, its own pricing, and its own learning curve. The result: employees spend more time managing their tools than doing their work. Managers spend more time chasing updates across platforms than making decisions. Founders spend more time on integration and maintenance than on growth.

This is a $200B problem. And it's getting worse as the average tool count per company grows each year.

### Why Aquerii Wins

Three reasons, and they compound:

**1. Unified data model.** Every module — Projects, CRM, ERP, HR, Meetings, Documents — is built on a single data graph. A contact in CRM is the same record as a customer in ERP. A project in the workspace is linked to the deal that created it. An employee record in HR powers the expense claim workflow in ERP. No duplication. No sync errors. No stale data.

**2. Zero-friction adoption.** Aquerii is designed to be set up in an afternoon, not a quarter. Unlike Salesforce (requires a consultant), NetSuite (requires a six-figure implementation), or Workday (requires an enterprise contract), Aquerii is self-serve from day one. Any manager can create their workspace, invite their team, and start working within 30 minutes.

**3. The network effect of consolidation.** Every tool a company replaces with Aquerii makes Aquerii more valuable. When the PM tool, the CRM, and the invoicing system are all in Aquerii, the cross-module automations become the moat. A company that uses all six modules cannot leave — not because we've locked them in artificially, but because the value of the integrated whole is greater than the sum of any individual parts.

### For Whom

**Primary:** SMB and mid-market companies (10–500 employees) across professional services, agencies, consulting, software, and operations-heavy businesses.

**Secondary:** Departments within larger enterprises that need a unified workspace without waiting for IT approval on a full enterprise rollout.

**Not for (yet):** Manufacturing-heavy companies that need deep supply chain management, hospitals requiring HIPAA-compliant medical records, or financial institutions requiring banking-grade compliance infrastructure.

## 6. Enterprise Features Required for Upmarket

These are non-negotiable for any mid-market or enterprise sale. Without these, the deal dies in security review.

### 6.1 Single Sign-On (SSO)

**Requirement:** SAML 2.0 and OAuth 2.0/OIDC support for all major identity providers (Okta, Azure AD, Google Workspace, OneLogin, Ping Identity).

**Implementation standard:**
- SP-initiated and IdP-initiated SSO flows
- Just-in-time (JIT) user provisioning on first SSO login
- Enforce SSO at the workspace level (block non-SSO login when enabled)
- Session duration controlled by IdP policy

**Why it matters:** Every company with 100+ employees uses an identity provider. If Aquerii doesn't support SSO, IT will reject the purchase. Full stop.

### 6.2 SCIM Directory Sync

**Requirement:** SCIM 2.0 API for automated user provisioning and deprovisioning from the identity provider.

**Implementation standard:**
- Create, update, deactivate users via SCIM
- Group sync: map IdP groups to Aquerii roles
- Real-time deprovisioning: when an employee leaves the company and is deactivated in Okta, their Aquerii access is revoked within minutes
- SCIM token rotation and audit

**Why it matters:** Manual user management at scale is a security liability and an ops burden. SCIM eliminates both.

### 6.3 Audit Logs

**Requirement:** Immutable, queryable audit log of every significant action in the platform.

**What must be logged:**
- Authentication events: login, logout, failed attempts, MFA events
- Data events: record created, updated, deleted, exported
- Admin events: role changes, permission changes, user invite, user deactivation
- Automation runs: trigger fired, action executed, errors
- API access: every API call with timestamp, user/token, endpoint, response code

**Implementation standard:**
- Minimum 2-year retention on Business tier
- Export to CSV or SIEM (Splunk, Datadog, ELK)
- Non-repudiation: logs cannot be altered or deleted by any user including workspace owner
- Real-time log streaming for Enterprise tier

**Why it matters:** SOC 2, ISO 27001, GDPR, and most enterprise security policies require audit logs. Without them, you cannot pass a security questionnaire.

### 6.4 Advanced RBAC

**Beyond the base hierarchy (Platform Owner → Company Owner → Manager → Employee):**

- Custom roles: create a "Finance Read-Only" role or a "Client Collaborator" role with exactly the permissions required
- Module-level permissions: restrict access to ERP to Finance team only
- Field-level permissions: hide salary fields from non-HR roles
- Record-level permissions: a sales rep can only see their own deals
- IP allowlisting: restrict access to company network or VPN only

### 6.5 SLA and Uptime

**Business tier SLA:** 99.9% uptime = maximum 8.7 hours downtime per year  
**Enterprise tier SLA:** 99.99% uptime = maximum 52 minutes downtime per year

**Required infrastructure:**
- Multi-region deployment with automatic failover
- Status page (public, real-time)
- Incident response playbook and communication protocol
- RTO (Recovery Time Objective): 1 hour for Business, 15 minutes for Enterprise
- RPO (Recovery Point Objective): 1 hour for Business, 5 minutes for Enterprise

### 6.6 Custom Domains

**Requirement:** Enterprise customers can run Aquerii on their own subdomain (e.g., `workspace.acme.com`).

**Implementation:**
- DNS CNAME or A record pointing to Aquerii infrastructure
- Automated SSL certificate provisioning via Let's Encrypt / ACM
- White-label login page with company logo and colors (optional)
- Email notifications sent from customer's domain

### 6.7 Data Residency

**Requirement:** Customers in the EU, UK, or regulated industries need their data stored in a specific geographic region.

**Implementation:**
- US region (default)
- EU region (Frankfurt/Ireland)
- APAC region (Singapore/Sydney)
- Data residency selection at workspace creation, locked thereafter
- Clear documentation of data flows for GDPR Article 30 record

### 6.8 Security Certifications (Roadmap)

**Priority order:**

2. SOC 2 Type II — 6 months after Type I

## 7. Non-Negotiable UX Principles

These are not aspirations. They are engineering constraints. Any feature that violates these principles does not ship.

### Principle 1: Under 100ms for All Interactions

Every click, every keystroke, every drag-and-drop must respond in under 100ms. Not "the server responds in under 100ms" — the UI responds in under 100ms, even if the server is still processing.

**Implementation:** Optimistic UI everywhere. When a user marks a task complete, the UI updates instantly. If the server call fails, we roll back gracefully. Users must never wait for the server to see the result of their action.

**Why:** Users have been trained by Linear, Figma, and Notion. Slow UIs feel broken. A 300ms lag on a button click feels like a bug, not a feature.

### Principle 2: Real-Time Collaboration Is Not Optional

Multiple users must be able to work in the same space simultaneously with zero conflicts and full visibility.

**Requirements:**
- Presence indicators: see who else is in the document, on the board, in the pipeline
- Live cursors in documents and real-time text sync (CRDT or OT)
- Instant updates across all sessions: if user A moves a task, user B sees it in under 500ms
- Conflict resolution: last-write-wins is not acceptable for documents; operational transforms or CRDTs are required
- Real-time notifications: @mentions, task assignments, comments — delivered instantly via WebSocket, not polling

### Principle 3: Zero Training Curve for Core Workflows

A new user must be able to complete their first core workflow (create a task, log a deal, send an invoice) without reading a tutorial.

**How we measure this:** We bring in 10 people who have never seen Aquerii and ask them to complete a specific workflow. If more than 2 of them cannot complete it in under 5 minutes without help, we redesign.

**Implementation patterns:**
- Empty states that guide: when a board is empty, show "Add your first task" with a clear affordance
- Inline help: tooltips and contextual help on first use, dismissable
- Progressive disclosure: show simple options first, reveal advanced options on demand
- Consistent patterns: if you know how to create a task, you know how to create a deal. Same modal, same fields pattern, same keyboard shortcuts.

### Principle 4: Mobile Is Not an Afterthought

Aquerii must have a responsive web app that works on mobile and a native mobile app (iOS + Android) for the core workflows that happen on the go: checking notifications, updating deal status, submitting expenses, clocking in/out, approving requests.

**The test:** A sales manager should be able to manage their entire pipeline from a taxi between client meetings. An employee should be able to submit an expense claim from their phone while at a restaurant.

### Principle 5: The Aesthetic Must Be 10/10

Aquerii's UI must be the most beautiful platform in its category. Not "clean and functional." Not "good for enterprise software." Beautiful. The kind of UI that makes users feel good about using it — that feels crafted, not assembled.

**Reference points:** Linear (density + speed), Figma (real-time + presence), Stripe Dashboard (clarity + typography), Notion (flexibility + whitespace).

**What 10/10 aesthetic means in practice:**
- Consistent spacing system (4px base unit, multiples of 4)
- Typography: one primary typeface, maximum 3 weights, clear hierarchy
- Color: a primary brand color, semantic colors for status (success, warning, error, info), neutral palette for UI chrome
- Iconography: one icon set, consistent size, consistent stroke weight
- Dark mode: not an inversion of light mode — a purpose-built dark palette
- Animations: meaningful, 150–250ms, ease-in-out, never decorative-only
- Density: two modes — comfortable (default) and compact (power users)

**The competitor benchmark:** F:\project-management represents the current reference. Aquerii must be aesthetically superior in every dimension: color, typography, spacing, animations, iconography, and overall coherence.

### Principle 6: Performance Is a Feature

- Initial page load: under 2 seconds on a standard broadband connection
- Time to interactive: under 1 second after initial load (client-side routing)
- Large datasets: a project with 1,000 tasks must render without lag (virtual scrolling)
- Offline capability: read access to recently-viewed data when connection drops; queue writes for when connection resumes
- Bundle size: monitored, budgeted, never allowed to balloon

### Principle 7: Keyboard-First Power Users

Every action that a power user does repeatedly must have a keyboard shortcut.

**Required shortcuts:**
- `Cmd/Ctrl + K` — command palette (search everything, take any action)
- `C` — create new record in current context
- `E` — edit focused record
- `Space` — preview record
- `G then P` — go to Projects
- `G then C` — go to CRM
- `G then E` — go to ERP
- `/` in documents — slash command menu
- `@` — mention a person or record
- `[[ ` — link to a record

The command palette (`Cmd+K`) is the power user's best friend. It must be able to do anything: navigate to any page, create any record, run any automation, search any data.

## 9. Risks and Mitigation

### Risk 1: Depth vs. Breadth Trade-off

**The risk:** Building 8 modules means each module is shallower than a best-of-breed point solution. A dedicated Salesforce customer won't switch for a CRM that's 80% as capable.

**Mitigation strategy:**
- We don't chase the enterprise Salesforce customer on day one. We target companies that are not yet using a dedicated CRM, or that are using lightweight tools (Pipedrive, HubSpot Starter) and need to consolidate.
- We prioritize depth in the modules where we have the most immediate competition: PM and CRM first, then ERP, then HR.
- We build a "power user escape hatch": for any module where we're not deep enough, we provide native integrations that allow the data to flow into a specialist tool without losing the unified data model.
- We track module-specific NPS separately. If CRM NPS is 30 and PM NPS is 70, we know exactly where to invest next.

**Timeline:** By month 18, every core module must be defensible against its primary point-solution competitor for the SMB/mid-market segment.

### Risk 2: Performance at Scale

**The risk:** A unified data model that spans PM + CRM + ERP + HR is a complex graph. As data grows (a company with 3 years of deals, invoices, projects, and employees), query performance degrades.

**Mitigation strategy:**
- Database architecture decisions made for scale from day one: proper indexing, materialized views for report queries, separate read replicas for analytics
- Query performance budget: every page must load its data in under 200ms at p95 for accounts up to 100,000 records
- Regular load testing with realistic data volumes (a company that has used Aquerii for 3 years)
- Async processing for heavy operations: report generation, data exports, bulk imports run in background jobs and notify when complete

### Risk 3: Security Incident

**The risk:** A breach of a platform that contains a company's deals, employees, financial data, and communications would be catastrophic — both for affected customers and for Aquerii's reputation.

**Mitigation strategy:**
- Encryption at rest (AES-256) and in transit (TLS 1.3) from day one
- No exceptions: every piece of customer data is encrypted
- Penetration testing by a third party before public launch and annually thereafter
- SOC 2 Type I within 6 months of launch
- Bug bounty program from public launch
- Incident response plan documented, tested, and rehearsed quarterly
- No storing of plaintext passwords — bcrypt + salt minimum, Argon2 preferred
- MFA enforced for Business tier accounts by default

### Risk 4: Adoption Friction — "Another Tool to Learn"

**The risk:** The all-in-one positioning is also a selling challenge. "We have to migrate our PM tool AND our CRM AND our accounting?" The consolidation benefit is real, but the migration effort is a real objection.

**Mitigation strategy:**
- Best-in-class data importers: CSV import for every module, native importers for common tools (Trello, Asana, HubSpot CSV, QuickBooks export)
- Phased adoption path: teams can start with just PM and add modules one by one. They don't have to migrate everything on day one.
- Migration concierge service (Business tier): a dedicated Aquerii team member who does the migration for the customer
- "Run in parallel" mode: let customers import historical data while using their old tools, then cut over when ready

### Risk 5: Engineering Complexity and Technical Debt

**The risk:** Eight modules with real-time collaboration, a shared data model, automations, and an API is a massive engineering surface area. Without architectural discipline, this becomes unmaintainable.

**Mitigation strategy:**
- Modular monolith architecture: modules are separate code domains within a monolith, not microservices. This gives development velocity early while maintaining the option to extract services later.
- API-first: every module's functionality is exposed through a well-defined internal API before building the UI. This enforces separation of concerns and enables external API access without rework.
- Test coverage as a constraint: no feature ships below 80% test coverage on core flows. Automation and ERP module especially.
- Technical debt sprint: every 6th sprint is a debt sprint — no new features, only refactoring, performance, and test coverage improvement.

### Risk 6: Pricing Pressure from Competitors

**The risk:** If Aquerii gains traction, Monday.com, ClickUp, and HubSpot will respond with pricing changes or feature parity. They have more resources and can sustain price competition longer.

**Mitigation strategy:**
- The moat is not price — it's the unified data model and cross-module automations. No competitor can replicate this in 12 months without fundamentally rearchitecting their platform.
- Build network effects within companies: the more modules a company uses, the harder it is to leave. A company using PM + CRM + ERP + HR cannot disentangle those modules without significant cost.
- Focus on the customer success motion: high NPS customers don't churn on price. Build the kind of product that generates genuine loyalty.
- Community and ecosystem: build an Aquerii marketplace for templates, automations, and integrations. Third-party extensions increase switching costs.
